Setup

Designed to protect cloud-hosted Linux VMs

Not designed for local machines.

Copy the prompt to your coding agent. It installs Lookout on the Linux VMs you approve.

Agent instruction 
Install Lookout on Linux VMs I approve using the Lookout CLI.

1. Run `lookout version`. If unavailable, install the CLI without `sudo`:
- macOS or Linux: download `https://app.devlookout.com/cli/install.sh` to a temporary file using `curl --proto '=https' --tlsv1.2 --fail --silent --show-error --location`, run it with `sh`, delete only that exact file with `unlink` in a separate command, and add `$HOME/.local/bin` to PATH. Never use `rm`, globs, recursive deletion, or a compound command for cleanup.
- Windows: download `https://app.devlookout.com/cli/install.ps1` to a temporary file using `Invoke-WebRequest`, run it with PowerShell, delete it, and add `$env:LOCALAPPDATA\Lookout\bin` to PATH.
Run `lookout version` again.

2. Ask which private network I want to monitor. If you don’t have access, ask how to access it. Then scan the VMs in that network, give me the list, and ask which VMs I want to install Lookout security observability on.

3. Then exhaustively verify administrative access to each selected VM. Report Needs access for inaccessible VMs and continue when all are accessible.

4. Add each VM with `lookout vm add --name NAME --address PRIVATE_IP`. Add `--ssh-host SSH_HOST` if an access check used a hostname or SSH alias, using that exact value. Add `--ssh-user USER` only when required by existing SSH configuration. Then run `lookout vm central NAME` on the first VM on the list.

5. Say exactly: “For security, I’ll let you complete the browser authentication and verification-code process yourself. Run `$HOME/.local/bin/lookout login` in another terminal, or `& "$env:LOCALAPPDATA\Lookout\bin\lookout.cmd" login` on Windows. When finished, reply `done`.” End your turn and wait. After I reply `done`, run `lookout install` and wait for it to finish.

6. If installation fails, run `lookout diagnose` and fix the reported problem. Then run `lookout install --retry`. The CLI resumes a saved deployment when possible and otherwise starts a new installation attempt. If still blocked, run `lookout report`, complete the generated survey with the PT timestamped attempt history and exact error, then run `lookout report submit SURVEY_FILE`. Do not include credentials or private keys. If reporting is needed before login, ask me to run the exact installed CLI path from step 5 in a separate terminal first.

7. Report installed VMs, failures, and coverage gaps.

Choose one private network and approve the exact Linux VMs before the agent configures or installs anything.

Use only the saved deployment ID, VM records, provider context, addresses, SSH users, and available access methods. Try a recorded management transport when present, then only other provider-native methods for that same VM. Do not run cloud inventory, scan networks, rediscover VMs, or probe unrelated hosts. Continue only if its deploymentId matches the saved deployment. If the marker is missing or different, do not modify the VM and report it as not installed for this deployment.

Uninstall collectors first and the central VM last. On every verified VM, run only:
